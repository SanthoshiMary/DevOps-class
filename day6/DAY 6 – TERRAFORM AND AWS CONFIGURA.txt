1. INTRODUCTION TO TERRAFORM
----------------------------

Terraform is an Infrastructure as Code (IaC) tool developed by HashiCorp.

It allows us to create and manage infrastructure using configuration files instead of manually creating resources through the cloud provider's web console.

Terraform can be used with cloud platforms such as AWS, Azure, and Google Cloud.


2. INFRASTRUCTURE AS CODE (IaC)
-------------------------------

Infrastructure as Code means managing and creating infrastructure using code.

Instead of manually creating cloud resources through a web console, we can define the required infrastructure in configuration files.

Benefits of Infrastructure as Code:

- Infrastructure can be created using code.
- Configuration can be version controlled using Git.
- Resources can be created consistently.
- Infrastructure can be automated.
- Manual work can be reduced.


3. TERRAFORM WORKFLOW
---------------------

The basic Terraform workflow is:

Write Configuration
        |
        v
terraform init
        |
        v
terraform plan
        |
        v
terraform apply
        |
        v
Infrastructure Created


terraform init:
Initializes the Terraform working directory and downloads the required provider plugins.

terraform plan:
Shows the changes Terraform is going to make before applying them.

terraform apply:
Applies the Terraform configuration and creates or modifies the required infrastructure.

5. AWS IAM
----------

IAM stands for Identity and Access Management.

AWS IAM is used to control who can access AWS resources and what actions they are allowed to perform.

IAM can be used to manage:

- Users
- Groups
- Roles
- Permissions
- Access Keys


6. CREATING AN IAM USER
-----------------------

I created a separate IAM user for working with AWS instead of using the root account for regular tasks.

The IAM user can be given the required permissions to access AWS resources.

Using a separate IAM user allows permissions to be controlled independently.

Basic flow:

AWS Account
     |
     v
    IAM
     |
     v
Create IAM User
     |
     v
Assign Required Permissions
     |
     v
Create Access Credentials


7. ACCESS KEY AND SECRET ACCESS KEY
-----------------------------------

After creating the IAM user, I configured credentials for programmatic access.

The credentials included:

- Access Key ID
- Secret Access Key

These credentials can be used by tools such as the AWS CLI and Terraform to authenticate with AWS.

IMPORTANT:

The Secret Access Key is sensitive information and should never be uploaded to GitHub or shared publicly.

AWS credentials should always be stored securely.


8. CONFIGURING AWS CREDENTIALS
------------------------------

I configured the AWS credentials in my local environment so that AWS-related tools can authenticate with my AWS account.

The configuration allows tools running on my system to communicate with AWS.

The overall flow is:

IAM User
    |
    v
Access Key ID + Secret Access Key
    |
    v
AWS Configuration
    |
    v
Local Machine
    |
    v
Terraform / AWS CLI
    |
    v
AWS Services


9. TERRAFORM AND AWS INTEGRATION
--------------------------------

Terraform can use the AWS provider to communicate with AWS and manage AWS infrastructure.

The basic concept is:

Terraform
    |
    v
AWS Provider
    |
    v
AWS Credentials
    |
    v
AWS Account
    |
    v
AWS Resources

Terraform configuration files can be used to define the AWS infrastructure that needs to be created and managed.
